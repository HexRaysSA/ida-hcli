**Research complete. Here's what I found:**

## 1. Plugin Sources/Repositories

Repos are configured in `ida-config.json` under `.Settings.plugin-repositories`. The `AggregatePluginRepo` (`repo/aggregate.py`) wraps named repos and lazily fetches them. There are concrete repo types:
- `FileSystemPluginRepo` (`repo/fs.py`): walks a directory, indexes every `.zip` it finds
- `JSONFilePluginRepo` (`repo/file.py`): deserializes a static `{version: 1, plugins: [...]}` JSON document
- `GithubPluginRepo` (`repo/github.py`): searches GitHub
- `PluginBundleRepo` (`repo/bundle.py`): offline bundles

When installing with a plugin reference like `community/foo`, `repo_for_reference()` in `commands/plugin/__init__.py:182` resolves which child of the aggregate to query.

## 2. Fetch/Download Flow

`BasePluginRepo.fetch_compatible_plugin_from_spec()` resolves the spec (name + optional version pin) against platform and IDA version, finds a `PluginArchiveLocation` (url, sha256, metadata), downloads via `fetch_plugin_archive()`, verifies the SHA-256 hash, returns `(plugin_name, bytes)`.

## 3. Source Tracking

A plugin's "source" is its `urls.repository` field (the `host` property). This stays embedded in the installed `ida-plugin.json`. Upgrade anchors to the installed host so it queries the same repo.

## 4. Version Resolution

`find_plugin_from_spec()` in `BasePluginRepo` (`repo/__init__.py:240-291`) parses specs like `name&gt;=1.0.0`, iterates versions descending by semver, filters by platform and IDA version, returns the first match.

## 5. Multi-Manifest Archives

`get_metadatas_with_paths_from_plugin_archive()` (`plugin/__init__.py:749`) enumerates every `ida-plugin.json` in a zip. `PluginArchiveIndex.index_plugin_archive()` indexes all of them. But the **install command** enforces `len(items) != 1` in 5 places (`install.py:132,140,149,168,183`). The repo-based path does NOT enforce this (it fetches by name, which naturally picks one).

## 6. Test Infrastructure

- Fixtures in `tests/lib/fixtures.py`: `virtual_ida_environment` sets `HCLI_IDAUSR`, `HCLI_CURRENT_IDA_PLATFORM`, `HCLI_CURRENT_IDA_VERSION`. `virtual_ida_environment_with_venv` adds a Python venv for pip tests.
- Test plugins in `tests/data/plugins/plugin1/`: src-v1 through src-v6 directories, each zipped. Makefile generates zips. Also `zydisinfo` for binary plugin testing.

- `test_plugin_install.py`: install, uninstall, upgrade, rollback, broken directories, archive validation
