## 3. How extraction works

**File:** `/Users/user/code/hex-rays/ida-hcli/src/hcli/lib/ida/plugin/install.py`, function `extract_zip_subdirectory_to()` (line 681-738).

The extraction is into a **named subdirectory** -- specifically `$IDAUSR/plugins/&lt;plugin-name&gt;`. The key details:

- The `subdirectory` parameter indicates which directory inside the ZIP contains the plugin (the parent of where `ida-plugin.json` was found). If `ida-plugin.json` is at the archive root, `subdirectory` is `Path(".")` and the prefix becomes empty string `""`, meaning all entries are candidates.
- If `ida-plugin.json` is inside e.g. `src-v2/ida-plugin.json`, then `subdirectory` is `Path("src-v2")` and only entries under `src-v2/` are extracted. The `src-v2/` prefix is stripped, so files land directly inside the destination.
- Extraction uses a **staging directory** in a trash area (`$IDAUSR/.plugins-trash/&lt;name&gt;.staging-&lt;uuid&gt;`) on the same filesystem. All files are extracted there first, then the staging dir is atomically renamed to the final destination via `os.rename()`. This ensures the plugin directory appears all-at-once or not at all.
- If anything fails, the staging directory is cleaned up (`shutil.rmtree`).

**Filtering logic** (`should_extract_plugin_archive_path`, line 657-678):
- Only entries under the plugin's subdirectory prefix are extracted.
- The plugin directory entry itself is skipped.
- `.git/` directories are skipped (to handle manually archived repos).

**Security validation** (`validate_archive_entry`, line 629-654):
- A full validation pass runs before any extraction begins (line 706-711).
- Rejects symlinks (Unix symlink bit `0xA` in `external_attr`).
- Rejects absolute paths.
- Rejects path traversal (`..` in path components).
