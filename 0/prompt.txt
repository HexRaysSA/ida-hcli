5. **Problem Solving:**

   Established the complete picture and verified it against the shipped IDA product rather than assuming. Findings to be written up:
   - `ida-config.json` keys hcli touches: `Paths.ida-install-dir` (written by IDA's `py-activate-idalib.py` and by hcli's install/set-default/switch; read by `idapro` and by hcli as last-resort fallback), `Settings.plugin-repository.url` (hcli only), `Plugins.<name>.settings` (hcli only). The IDA GUI/kernel binaries and the IDA installer never touch this file (issue #155).
   - hcli's own store: `ida.instances`, `ida.default`, `idb.sources` (+ legacy `idb.search-paths`), credentials.
   - Nine defects: (1) two pointers with the private one winning; (2) `hcli ida switch` deliberately diverges for non-idalib editions; (3) `hcli ida set-default PATH` is inert while `ida.default` is set, yet is still recommended in help text and docs; (4) hcli never sets `IDADIR` for child Python processes, so `hcli ida python run-script` picks the interpreter from hcli's install while `import idapro` inside the script binds to `ida-config.json`'s; (5) `hcli ida remove --all` or a moved install silently changes the current installation via fallback; (6) two competing notions of "installations that exist" (registry vs discovery); (7) `set_ida_config()` silently drops unknown JSON keys (verified experimentally); (8) `hcli ida remove` doesn't uninstall yet install.py suggests it for reinstalling; (9) hcli splits `$IDAUSR` on the path separator while IDA's `config.py` does not.
   - Proposed direction: make `ida-config.json:Paths.ida-install-dir` the single persistent selection; resolution becomes `$HCLI_CURRENT_IDA_INSTALL_DIR` → `$IDADIR` → `ida-config.json`; keep discovery as the source of "what exists" with names derived via `generate_instance_name()`; migrate in `ConfigStore._migrate_config` (adopt `ida.default` when `ida-config.json` is missing/invalid, notice once when they differ, then drop the keys). Known cost: switching to a Home/Free edition repoints idalib at an install with no `libidalib`, breaking `import idapro` until switched back — one loud warning is preferred over permanent invisible divergence.
   - Touch list: `lib/ida/__init__.py`, `commands/ida/{switch,list,add,remove,set_default,install}.py`, `lib/ida/launcher.py:155`, `main.py`, `lib/config`, `tests/lib/test_ida.py`, docs (`ida-detection.md`, `environment-variables.md`, `quick-start.md`, `installing-ida.md`; issue #193 already tracks the switch/set-default doc drift). Separately: fix `set_ida_config`'s lossy round-trip.
   - The four open decisions: (a) unify on ida-config.json (drop `ida.default`) vs keep both and always write both vs invert precedence; (b) fate of `ida.instances` — delete and rely on discovery + derived names, keep as an unnamed "extra paths" list, or keep as-is; (c) when nothing is configured, auto-select the newest discovered install (reporting the source) vs keep erroring; (d) CLI verbs — `switch` as the one verb with `--set-default` retained on install and `set-default` as a deprecated alias that finally works, vs un-deprecating `set-default`, vs both first-class.
