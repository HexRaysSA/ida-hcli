## 3. Status (`src/hcli/commands/plugin/status.py`)

**Discovery** (lines 149–198, `collect_status_report`):
- `get_installed_plugin_records()` — iterates `$IDAUSR/plugins/`, reads `ida-plugin.json` for each immediate child dir where `metadata.plugin.name == path.name`
- Also discovers "incompatible" plugins (`get_installed_minimal_plugins`) and "legacy" single-file plugins (`get_installed_legacy_plugins`)
- Each record becomes an `InstalledPluginStatusEntry` with optional upgrade check against repo

**Display** (lines 201–240, `render_status_report_text`):
- Table columns: name, version, status (upgrade info)
- No component count, no `--show-components` flag
- JSON output: `StatusReport(plugins=[...])` — flat list, no `components` sub-array

**Key: `get_installed_plugin_records()`** (`install.py:299–339`) does a **one-level-deep** scan: it only looks at immediate children of `$IDAUSR/plugins/`. This means nested component manifests are NOT discovered as top-level plugins. This is the correct behavior per the design doc. But component directories *inside* a suite directory are silently skipped since `metadata.plugin.name != plugin_path.name` (line 333) — the name is the suite's component name, but path.name would be the subdirectory within the suite.
