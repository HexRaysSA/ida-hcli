2. Key Technical Concepts:
   - `components` field: `list[str]` on `PluginMetadata` for declaring tightly-coupled plugin suites. Components are subdirectories bundled inside the suite's archive, share the suite's lifecycle, hidden from top-level listings.
   - `dependencies` field: Already implemented loose coupling where plugins are fetched individually and installed as independent top-level plugins.
   - Component tree walking: Recursive traversal from directories and archives, depth-limited to 10 (matching IDA's `enumerate_fs_recursive`).
   - Root manifest identification: In multi-manifest archives, the root is the manifest not referenced as a component by any other manifest.
   - Name collision checking: Component names checked against all installed top-level plugins and other suites' components.
   - `get_installed_plugin_records()` is one-level-deep — components in nested dirs are naturally hidden.
   - `extract_zip_subdirectory_to()` extracts full subtrees — component subdirectories come for free.
   - Trash-and-replace upgrade mechanism handles suite upgrades atomically.
